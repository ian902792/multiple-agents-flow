怎麼選 flow？

Quick · 小任務

Claude 在主對話直接開發；完成並提交後，用 Codex Sol 獨立 review。若有明確的小範圍工作，可讓 Pi 在獨立 worktree 處理。

  1. 選 quick 並按「儲存並使用」。
  2. 在 Claude 描述需求；需要時輸入 /maf delegate 需求。
  3. 完成並 commit 後輸入 /maf verify 需求。

Planned · 中大型任務

你決定何時請 Codex Astra 規畫；Claude 再實作、把輕量任務交給 Pi，最後用獨立 review 與測試驗證。

  1. 選 planned 並按「儲存並使用」。
  2. 手動輸入 /maf-plan 需求，確認計畫。
  3. 請 Claude 實作；必要時 /maf delegate，提交後 /maf verify。

自訂 · 常用專案流程

按「新增 flow」，調整主 Claude 偏好與各角色的模型、effort，命名後儲存。之後在左側選它並按「儲存並使用」；可匯出 JSON 到另一個 workspace。

模型升級

主 Claude 偏好可用 opus 跟隨最新 Opus；自動化角色宜用固定版本，例如 claude-opus-5-5。Codex 以明確 ID 選型號，例如 gpt-6-sol。MAF agent 模型改變後，使用該訂閱路由前須重新確認。參考 Claude 模型文件與 Codex 模型文件。

安裝與使用指南

MAF 把日常開發留在 Claude；Pi 只接範圍清楚的任務，Codex 只在手動規畫或獨立審查時啟動。短任務上下文、程式測試與對應同一 commit 的 review，讓交接更精簡，也較容易追查結果；實際 token 用量仍取決於任務與模型。

Claude 主對話→可選：Pi 小任務→程式測試→Codex 獨立 review→同一 commit 的證據

1 · 準備工具與專案

需要 Python 3.11+、Git、Claude Code；預設 flow 的 doctor 會檢查 Codex CLI 與 Pi CLI 的登入。目標資料夾須是已有第一個 commit 的 Git repository；Herdr 是可選的 workspace 管理工具。若工具 repository 尚未公開，請先取得存取權。

git clone https://github.com/ian902792/multiple-agents-flow.git
cd multiple-agents-flow
FLOW="$PWD/flow.py"
TARGET="/path/to/your-git-project"

2 · 在目標專案啟用

--repo 要放在子命令前。init 建立專案設定，install-skills 只註冊該專案的 Claude／Codex skill；不改全域設定。

python3 "$FLOW" --repo "$TARGET" init
python3 "$FLOW" --repo "$TARGET" install-skills
python3 "$FLOW" --repo "$TARGET" mode quick
python3 "$FLOW" --repo "$TARGET" doctor
python3 "$FLOW" --repo "$TARGET" ui

3 · 確認訂閱後開始

先在各供應商檢查登入、所選模型是否包含在現有訂閱，以及額外用量／餘額是否關閉。doctor 不會呼叫模型，也不能證明訂閱涵蓋。確認後再執行：

python3 "$FLOW" --repo "$TARGET" confirm-billing --no-overage
python3 "$FLOW" --repo "$TARGET" doctor

接著在目標專案重新開啟 Claude 對話，輸入 /maf status；小任務用 /maf mode quick，大型任務先用 /maf mode planned，需要規畫時再手動 /maf-plan 需求。完整 CLI 範例見專案 README。

  • flow 只影響新任務；已提交任務保留原本模型快照。
  • 切換 flow 不呼叫模型，也不會替你切換目前 Claude 對話。
  • 測試由程式執行，獨立審查必須對應同一個精確 commit SHA；未驗證的 agent 自述不算完成。
