怎麼選 flow？

Quick · 小任務

Claude 在主對話開發；完成並提交後，用 Codex Sol 獨立 review。明確的小範圍工作才交給 Pi。

  1. 在專案的 Claude terminal 輸入 /maf mode quick。
  2. 請 Claude 開發；必要時輸入 /maf delegate 需求。
  3. commit 後輸入 /maf verify 需求。

Planned · 中大型任務

由你決定何時請 Codex Astra 規畫；Claude 負責整合，Pi 處理明確小任務，最後測試與獨立 review。

  1. 輸入 /maf mode planned。
  2. 需要規畫時手動輸入 /maf-plan 需求，檢查計畫。
  3. 互不依賴的小工作可一起 delegate 給多個 Pi；Claude 整合、commit 後 verify。

自訂 · 跨專案常用流程

按「新增 flow」，寫清適用範圍、調整模型與 effort 並儲存。例如命名為 docs-review。在任一專案的 terminal 輸入 /maf mode docs-review；每個專案的選擇各自保存。

模型升級

主 Claude 偏好可用 opus 跟隨最新 Opus；自動化角色宜用固定版本，例如 claude-opus-5-5。Codex 以明確 ID 選型號，例如 gpt-6-sol。MAF agent 模型改變後，使用該訂閱路由前須重新確認。參考 Claude 模型文件與 Codex 模型文件。

任務核准：只在起點與例外時打擾你

小任務依照你已提出的需求直接做；較大或敏感的任務先由 Claude 列出目標、可修改路徑、測試指令、模型角色、修復次數與發布動作。你確認一次後，同一個 run 會自動完成實作、測試、獨立 review 與範圍內的修復。

何時停在起點？

敏感檔案、過寬的路徑、shell 測試、手動風險的獨立 coder 任務，或明確加上 --require-approval 時，run 會顯示 awaiting_approval。先看完整 status RUN_ID；確認後使用 /maf approve RUN_ID 或 CLI approve RUN_ID。若對話中已核准同一份具體計畫，不需再問一次。

何時再問你？

需求衝突、權限或資安風險需要決定時，run 停在 needs_human/replan，不會自行重試。範圍或測試要改時建立新任務；普通測試失敗和可修的 review 問題會在既定修復次數內自動處理。核准本機執行不代表允許 push 或合併。

主 Claude 對話由 /maf skill 遵守這項約定；MAF CLI 只約束它啟動的子任務。Flow Studio 負責設定 flow，不提供任務核准按鈕。

可選整合 · Herdr

關閉（預設）

在一般 terminal 執行 work，用 progress／/maf status 看狀態；不建立 Herdr workspace 或 agent pane。

啟用

在 Herdr pane 執行 herdr：MAF 建立不搶焦點的 supervisor workspace，更新主任務 pane 的進度標題；每個 coder／reviewer 執行時會開自己的暫時 pane 顯示即時事件與工具類型，完成後自動關閉。從 Herdr 手動執行 /maf-plan 也會為 planner 開暫時 pane。

這些 pane 只供觀察；agent 仍由 supervisor 管理，正式結果以測試與 commit 證據為準。原始輸出保存在私有 log，pane 不顯示 prompt 或全文。獨立 Pi 任務可同時顯示多個 pane，預設最多兩個任務。此開關只允許整合，不會自行啟動 worker；啟用後仍須在 Herdr 內明確輸入 python3 "$FLOW" --repo "$TARGET" herdr。若只跑一次，可用 work --once --run-id RUN_ID --agent-panes，多個任務可重複 --run-id。

安裝與使用指南

MAF 把日常開發留在 Claude；Pi 只接範圍清楚的任務，Codex 只在手動規畫或獨立審查時啟動。短任務上下文、程式測試與對應同一 commit 的 review，讓交接更精簡，也較容易追查結果；實際 token 用量仍取決於任務與模型。

Claude 主對話→可選：Pi 小任務→程式測試→Codex 獨立 review→同一 commit 的證據

1 · 全域安裝一次

需要 Python 3.11+、Git、Claude Code；預設 flow 的 doctor 也會檢查 Codex CLI 與 Pi CLI。下載工具後，只執行一次 install-skills，在使用者目錄註冊 Claude 的 /maf、/maf-plan 與 Codex 的 $maf。不需在每個專案重裝；若 repository 尚未公開，先取得存取權。

git clone https://github.com/ian902792/multiple-agents-flow.git
cd multiple-agents-flow
FLOW="$PWD/flow.py"
python3 "$FLOW" install-skills
python3 "$FLOW" ui

2 · 每個專案只建立政策

在目標 Git 專案開啟 Claude，輸入 /maf setup quick 即可初始化並選 mode；不再安裝 skill。CLI 等價指令如下，--repo 放在子命令前。目標專案需已有第一個 commit。

TARGET="/path/to/your-git-project"
python3 "$FLOW" --repo "$TARGET" init
python3 "$FLOW" --repo "$TARGET" mode quick
python3 "$FLOW" --repo "$TARGET" doctor

3 · 確認訂閱後開始

在供應商確認登入、所選模型包含於現有訂閱、額外用量／餘額扣款已關閉。doctor 不呼叫模型，無法證明訂閱涵蓋。確認後執行：

python3 "$FLOW" --repo "$TARGET" confirm-billing --no-overage
python3 "$FLOW" --repo "$TARGET" doctor

接著在目標專案重新開啟 Claude 對話，輸入 /maf status；小任務用 /maf mode quick，大型任務先用 /maf mode planned，需要規畫時再手動 /maf-plan 需求。完整 CLI 範例見專案 README。

4 · 互不依賴的小工作可交給多個 Pi

在同一則需求中列出各自的工作與驗收方式，例如「同時補 docs/install.md 安裝說明與 docs/faq.md 常見問題，各自檢查」。Claude 先從同一個乾淨 commit 建立兩份任務，標記 independent: true，再讓 MAF 執行。預設最多兩個 Pi 任務同時跑；每件有自己的 worktree、測試、review 與暫時 Herdr pane。編輯檔案重疊、路徑太廣或需要核准的任務會依序處理。並行縮短等待時間，但不保證總 token 變少。整合後的 commit 仍需重新 verify。

/maf delegate 同時處理：1. 補 docs/install.md 安裝範例；2. 補 docs/faq.md 常見問題；各自驗收。

使用 CLI 時，先各自 delegate TASK.json，再用 work --once --run-id ID1 --run-id ID2；完整範例見 README 與指令參考。

Claude terminal 指令 · 用法與輸出

以下在 Claude Code 的專案對話中輸入。Codex 用 $maf 或 /skills → maf；/maf-plan 是 Claude 專用手動規畫指令。結果會回報在目前對話中，格式依 host 略有不同。

指令用途輸出
/maf查看目前 mode 與進度模式、角色、阻塞摘要；未初始化時提示 setup
/maf setup quick初始化專案政策並選 flow專案設定路徑、doctor 結果與待確認事項
/maf mode [名稱]查看或切換本專案後續任務的 flow所選 mode、可用名稱、角色模型與 billing 狀態
/maf approve RUN_ID確認已檢視的凍結計畫並放行一次run ID、queued 與核准時間；範圍變更時拒絕
/maf delegate 需求把一件或數件獨立小任務交 Pi各任務的 run ID、驗證狀態、阻塞或 handoff
/maf verify 需求驗證 Claude 已 commit 的 HEADrun ID、測試與審查對應 SHA、結果
/maf handoff RUN_ID讀已驗證任務的交接精確 SHA、測試、審查與後續動作
/maf run 需求明確要求獨立 coder 的批次任務run ID、階段、結果或阻塞
/maf status只讀進度，不啟動 worker各 run 的階段、attention 與下一步
/maf resume RUN_ID診斷中斷後恢復是否可恢復、原因與新狀態
/maf install補做一次全域 skill 註冊Claude／Codex skill 路徑
/maf-plan 需求手動請 Codex 規畫大型任務計畫、拆工建議與私有結果路徑；不自動執行

底層 CLI 指令 · 用法與輸出

以下皆以 python3 "$FLOW" 開頭。需要專案的指令加 --repo "$TARGET"，放在子命令前；全域指令不需要。多數輸出是 JSON，失敗時印 flow: 原因 並回傳非零代碼。

子命令用途輸出
install-skills全域註冊一次skill 路徑與重新開啟 session 的提示
ui開啟本機設定頁MAF Flow Studio: http://127.0.0.1:PORT/
flows列出全域 flow{"flows": {...}}
flow-save FILE匯入 GUI 匯出的 JSON已驗證的 flow JSON
settings [herdr on|off]看或設定全域 Herdr 開關{"herdr_enabled": false} 或 true
init建立本專案 .maf.json設定路徑與下一步
mode [名稱]查看或切換本專案 mode模式、可用名稱、角色與 billing
doctor檢查 CLI／登入與訂閱確認紀錄各角色問題陣列、billing 問題；有問題時非零代碼
confirm-billing --no-overage記錄人已核對現有訂閱{"confirmed": true, ...}
plan --goal-file FILE [--mode NAME]手動只讀規畫計畫文字與私有結果路徑
submit TASK.json [--mode NAME] [--require-approval]排入獨立 coder 任務run JSON，含 ID、queued 或 awaiting_approval
delegate TASK.json [--mode NAME] [--require-approval]排入 Pi 小任務run JSON，含 ID、狀態與核准原因
verify TASK.json [--mode NAME] [--require-approval]排入目前 commit 的測試與審查run JSON，含 ID、source SHA 與狀態
approve RUN_ID放行一次已檢視的任務範圍run JSON，狀態變成 queued
work [--once] [--run-id ID ...] [--pi-concurrency N] [--agent-panes]處理佇列；獨立 Pi 任務預設同時兩個，Herdr 可開各自的觀察 pane每個任務的階段與結果，或無可執行任務的訊息
status [RUN_ID]列摘要或完整單一 runrun 陣列或單一 run JSON
progress [--json|--watch]讀進度，可選 JSON／持續監看階段、SHA、阻塞、下一步；JSON 不含 transcript
handoff RUN_ID讀已驗證證據精確 commit SHA、測試與 review 結果
resume RUN_ID [--acknowledge-stopped]人工診斷後恢復更新後 run JSON；條件不足時錯誤
publish RUN_ID已授權時發布或核對 PRPR URL／狀態或阻塞
merge RUN_ID已授權時合併或核對結果合併狀態或政策阻塞
herdr在 Herdr 內啟動 supervisor 與自動 agent paneworkspace ID、worker pane ID、主任務 pane ID

發布／合併的其他旗標與任務 JSON 格式見 README。選 mode 和儲存 flow 都不呼叫模型；plan、work 才可能啟動 agent。

範例 · 開關、切換與核准

python3 "$FLOW" settings                 # {"herdr_enabled": false}
python3 "$FLOW" settings herdr on        # {"herdr_enabled": true}
python3 "$FLOW" --repo "$TARGET" mode quick
# Claude terminal: /maf mode planned
# Claude terminal: /maf-plan 設計跨模組重構
# Claude terminal: /maf mode docs-review
# 若 run 回傳 awaiting_approval：/maf status RUN_ID → 確認 → /maf approve RUN_ID
  • flow 只影響新任務；已提交任務保留原本模型快照。
  • 切換 flow 不呼叫模型，也不會替你切換目前 Claude 對話。
  • 測試由程式執行，獨立審查必須對應同一個精確 commit SHA；未驗證的 agent 自述不算完成。
