    為什麼選 MAF

    多 agent 的做法很多，MAF 最在意兩件事

    宣稱完成時有沒有證據，以及會不會意外花錢。和 prompt 型 skill、同一家的子 agent、並行工作樹管理工具、按用量計費的 API 框架相比，差別在這裡：

    證據

    完成綁定同一個 commit

    測試與可選審查都要對同一個 SHA 通過；commit 一變，舊證據就作廢。不會把「agent 說做完了」當成做完。

    程式把關

    不靠模型自律

    可修改的路徑排入時就凍結，越界就停；中斷後不會自動重跑，額度或登入不明時停下。

    成本

    只用現有訂閱

    拒絕 API key 路由，額度用完就停，不會改用按量計費繼續跑。

    第二雙眼

    規畫與審查一定換一家

    Claude 對話交給 Codex 規畫，Codex 對話交給 Claude；同一家的組合會被擋下，避免同一種盲點。

    並行

    同時跑但不互相踩到

    最多 3 件，只限標記獨立、檔案不重疊、從同一個 commit 出發的任務，其餘照順序。

    輕巧

    留在對話，讀得完

    不必切到另一個管理介面，主 Agent 透過 skill 在背後委派與驗證。只用 Python 標準庫，沒有常駐服務或資料庫。

    也要知道的限制

    概念比 prompt 型 skill 多，上手要花一點時間；只支援 Claude、Codex、Pi、Antigravity、Hermes 等訂閱路線；工作樹不是安全沙箱，只在信任的 repo 使用；並行上限 3 件，只支援 macOS／Linux。已實測與尚未實測的範圍記在 驗證紀錄。

    大任務先規畫

    用 maf-plan 請另一家的強模型先想清楚

    需求大、牽涉多個模組，或你自己還沒想清楚時，先輸入一次 maf-plan。規畫者一定和主對話不同家，只讀、不改檔，換一雙眼睛抓出主對話自己看不見的假設。

    /maf-plan 需求
    主Claude 主對話quick、planned 等規Codex GPT-6 Astrahigh effort，只讀
    $maf-plan 需求
    主Codex 主對話codex-pi規Claude Opus 5.5可改 Fable 5.1，只讀
    1. 你手動呼叫只有你輸入 maf-plan 才會規畫，選到 planned 也不會自動啟動。
    2. 另一家模型規畫交回依賴順序、介面約定、風險與可執行的驗收命令。
    3. 你確認一次主 Agent 整理範圍、測試與風險給你看；計畫本身不授權任何執行。
    4. 主 Agent 接手照確認的範圍實作，明確的小任務再委派出去。

    規畫者和主對話是同一家時，MAF 會拒絕執行。在 Flow Studio 的「規畫 Agent」可以切換工具與模型，例如把 Codex 對話的規畫者改成 claude-fable-5-1。

    可選功能

    勾選 Herdr 之後，差在哪裡

    Herdr 是給 coding agent 用的終端機多工器。MAF 的結果不受它影響，差別在於你能不能一邊聊天、一邊看每個 agent 在做什麼。

    沒勾選（預設）
    主對話
    work 跑完才回來
    • 主 Agent 在前景執行 work --once，跑完才繼續對話。
    • 只看得到階段變化：coding → testing → tested。
    • 想知道進度，就問 /maf status。
    勾選 Herdr
    主對話
    pane 標題顯示進度
    supervisor
    MAF coder …
    • supervisor 在另一個 flow: 專案名 workspace 背景常駐，主 Agent 只要排入任務。
    • 每個執行中的 coder、reviewer 各開一個暫時 pane，顯示事件名稱與工具類型，結束後自動關閉。
    • 主 pane 標題即時顯示 maf 1/3 done | 2 running | …。
    • pane 只負責顯示，不是驗證證據；也不會顯示 prompt 或完整對話。

    在 Herdr pane 裡開一次（全域開關，之後每個專案都能用）：

    python3 flow.py settings herdr on

    在你的專案 pane 啟動 supervisor：

    python3 /path/to/flow.py --repo /path/to/your-project herdr
    設定一次

    四個步驟裝好

    需要 macOS 或 Linux、Python 3.11+、Git，以及 Claude Code 或 Codex。目標專案要是已有第一個 commit 的 Git repository；不必 init，也不用每個專案重裝。

    1. 安裝 skill

      git clone https://github.com/ian902792/multiple-agents-flow.git
cd multiple-agents-flow
python3 flow.py install-skills

      會註冊全域的 Claude /maf、/maf-plan 與 Codex $maf、$maf-plan。裝完記得重開主對話。

    2. 選預設 flow

      python3 flow.py ui

      在 Flow Studio 選好 flow，按「設為全域預設」。也可以直接指定：python3 flow.py settings default-flow quick

    3. 確認只用訂閱

      先到各家控制台確認模型包含在現有訂閱，額外付費用量和 OpenCode Go 的 Use balance 都已關閉，再記錄一次：

      python3 flow.py confirm-billing --no-overage

      之後換模型或路由要再確認一次。MAF 不會替你改帳單設定。

    4. 在專案裡直接說

      maf請按目前 flow 完成這項修改。路徑與驗收明確的小工作可以委派；完成後測試已提交的變更，告訴我結果與 commit SHA。

      接下來就是上面示範的流程。想先檢查環境，可以跑 python3 flow.py --repo 專案路徑 doctor，它不會呼叫模型。

    看懂狀態

    輸入 /maf status 會看到這些

    running

    小任務 Agent 正在施工，或 MAF 正在跑測試。

    讓它跑完，不用插話。

    tested

    沒開審查，指定測試已對這個 commit 通過。

    可以整合；還沒 push。

    verified

    測試與獨立審查都通過同一個 commit。

    發 PR 或合併仍要你另外授權。

    awaiting_approval

    範圍敏感或比較大，等你看過凍結的範圍。

    確認後說「放行」，只放行這一次。

    needs_human

    需求衝突、權限或資安問題，需要你決定。

    回答後，主 Agent 會建新任務，不會重跑舊的。

    waiting_quota

    訂閱額度用完或狀態不明，MAF 停住，不會改用 API。

    告訴主 Agent 額度什麼時候重置。

    用得順手

    新手最常問的幾件事

    • 指揮 MAF 時以「maf」開頭例如「maf改用 quick」「maf狀態」。flow、mode、planned 都是常見字，沒有 maf 開頭，agent 可能誤會成 CI 或 Claude Code 自己的 plan mode。
    • 委派後讓它跑完中途插話會讓主 Agent 停下來重新核對，白耗額度。臨時想法先記下來。
    • 一次只派現在就能驗收的任務下一件常取決於上一件交接裡的 UNVERIFIED 存疑項。
    • 委派前先 commitMAF 從乾淨的 HEAD 開始，不會替你 stash 或 reset。
    • 整合後要再驗證一次cherry-pick 會產生新的 SHA，舊證據不能套到新 commit。
    • tested、verified 都不等於已 push要 push、開 PR 或合併，開頭說一次就涵蓋整批任務；自己的 repo 可以在提示詞設定成驗證通過就自動合併。
    • 只在你信任的 repository 使用工作樹不是安全沙箱，測試會執行你核准的命令。

    常用說法（以 maf 開頭）

    maf同時處理 1. 補 docs/install.md 安裝範例；2. 補 docs/faq.md 常見問題；3. 補 docs/troubleshooting.md 疑難排解，各自驗收。
    maf這件的驗收重點是：重新整理後仍保持登入。
    maf改回全域預設。
